# code/s4-range

Programs that generated the Lean data modules of version 1.6.0 (`S4R_*`, `S4Range*`, `S4B_*`, `TCP_*`, `S4A_*`, `S4All_*` in `lean/LRSpectrumFull/`), and helpers for building them. The note is `paper/shifted-four-sum195/NOTE.md`.

**The generated Lean files are the data, and the data are trusted for nothing.** The Lean kernel checks them (`decide +kernel`) against soundness theorems that are proved in Lean (`d0_sound`, `tc_sound`, `classB_sound`, `rangeOK_sound`, `rangeOK2_sound`). Nothing in this directory is part of the trusted base; the programs are archived so that a reader can see how the data were produced, and so that the Rust mirror checks can be repeated. **Nothing in this directory was run for this release.** The sources are copies of the development sources, except for the edits named below.

## Contents

| Path | What it is |
|---|---|
| `gen/` | Rust crate `s4asm` (no dependencies; `cargo build --release`). One program, several modes, selected by the first argument. `census MAXS`: the class census over primitive vectors with sum at most `MAXS`, using the same lists and tests as the Lean `classB` (mirror; 195 gives 2,133,561 / 2,002,342 / 0 missed / 0 extra). `plan MAXS OUT`: table of (a,b) pairs with counts of vectors, class vectors and residual vectors. `genall PART OUTDIR [dry]`: writes the range modules `S4R_<aa>_<blo>_<bhi>.lean` for the intervals listed in the tab-separated file `PART` (columns `a`, `blo`, `bhi`); the depth-0 certificates are found by the search in `src/zono.rs` (`find_cert`). `gen A BLO N NAME OUT`: one range module (used for the five probe modules `S4Range*`). `verify FILES`: Rust mirror of the loop `rangeB` on the TEXT of module files (`MIRROR_TRUE` or `MIRROR_FALSE`). `check MANIFEST LEANDIR MAXS`: exactness of the partition into intervals (no gap, no overlap). `asmgen A BLO BHI TCFILE LEANDIR MAXINLINE MAXTC MAXOPS`: writes the blocked-range module `S4B_<aa>_<blo>_<bhi>.lean` and its time-cover modules `TCP_*` from the covers in `TCFILE`. `asmverify`, `asmcheck`: mirror and exactness checks for those modules. `blkgen`, `blkverify`: the first design of the blocked-range modules (the module `S4B_03_006_006` and `S4B_02_003_003` of the archive come from it). Source: `src/main.rs`, `src/block2.rs`, `src/blk.rs`, `src/blk2.rs`, `src/zono.rs`. |
| `tc-cover/` | Rust crate `tc_cert` (no dependencies). `gen LISTFILE OUTFILE QMIN QMAX EXTRA SEED` searches, for each vector of `LISTFILE`, time covers (a denominator `q` in `QMIN..QMAX` and a list of numerators) and writes one line per vector in the format of `data/certs305_a.txt`; `verify`, `perm`, `controls`: exact integer mirror of `tcOK` with a brute-force cross-check and negative controls. |
| `layers.py` | Python (standard library only, text generation, seconds): `python3 layers.py <path to lean/LRSpectrumFull>` writes `S4A_<aa>.lean` and `S4All_<k>.lean` from the range theorem statements found in the module files; it rewrites a file only if its text changed. Edited for the archive in one line (the path of the Lean directory became an argument). |
| `check_layers.py` | Python, `python3 -I check_layers.py <path to lean/LRSpectrumFull>`: parses the 175 range statements and the 47 + 5 layer modules and checks that the intervals of each `S4A_<aa>` are contiguous from `a + 1` to `(192 - a)/3`, that each cited theorem has the matching `(a, blo, n)`, and that the groups cover `a = 1..47`. A consistency check on the text, not part of the proof (the same fact is proved in Lean by `omega`). Output obtained for this release: `range theorem statements parsed 175`, `S4A files 1..47 checked; problems: 0`, `a>=48 infeasible: True`, `S4All a-coverage True`. Edited for the archive in one line (the path became an argument). |
| `build_modules.sh`, `launch_watchdog.sh` | Bash, written for macOS. `build_modules.sh TAG MODULE...` builds each module with `lake build LRSpectrumFull.<Module>`, strictly one after another, through `launch_watchdog.sh`, which starts the command, sums the resident memory of its whole process tree every 2 seconds, and kills the tree at 90 percent of the ceiling given as first argument (12000 MB in `build_modules.sh`, so 10800 MB), and also stops on a disk floor. Environment: `LEAN_DIR` (the directory `lean/` of the archive), `LOG_DIR`, `WATCHDOG` (path of `launch_watchdog.sh`). Edited for the archive only in paths and comments (a preflight comment and an unused variable were removed); the edited files were checked for shell syntax (`bash -n`) and were not run. They refuse to start a build if a Lean or Lake process is already running. |
| `data/v305.txt`, `data/certs305_a.txt` | the 305 vectors without a depth-0 certificate (input of `tc-cover`), and the time covers found for them (input of `asmgen`; one line per vector: the vector, `q`, the number of numerators, the number of mirror units, the numerators). |

## Notes for the reader

* The header comments that `gen` writes into the Lean files name the generator by a path of the development repository. In the four Rust files that write them (`gen/src/main.rs`, `block2.rs`, `blk.rs`, `blk2.rs`; five string literals) the leading directory of that path was deleted for the archive, so a run of the archived sources would write the same headers without that leading directory; the archived Lean files carry the original headers (the files were copied byte for byte). This deletion and the path and comment edits of the four scripts named in the table are the only changes made to the sources.
* The generator source was patched once after the binary that produced two of the modules had been compiled: in `blk2.rs` the nesting of `++` in the `preL_...` line was made right-associative (Lean's `++` is left associative, and the first output had the wrong nesting). The archived files `S4B_01_002_002.lean` and `S4B_01_003_003.lean` carry that line edited by hand to the right-nested form that the patched source writes (not checked by a run: the generator was not re-run).
* The exact command lines of the generation runs are not archived. The input of `genall` is a list of intervals; it can be read off from the file names `S4R_<aa>_<blo>_<bhi>` of the archive. The limits used for `asmgen` were: at most 30 covers and 450,000 mirror units per `TCP` module (the report of the assembly block).
* The deterministic search `find_cert` was restarted with different seeds during the work (40, then 3000 restarts) to confirm that exactly 305 vectors have no depth-0 certificate; the seed used for `data/certs305_a.txt` is not recorded.
* The partition of the 2,133,561 vectors into the intervals (the "manifest" of the development repository, with status columns and file hashes), the driver script that built the range modules one after another, the unattended finisher, and the memory-fit scripts are not archived: they depend on the layout of the development repository. The partition is visible in the file names and in the statements of the range theorems, and `check_layers.py` and the Lean case splits `S4A_<aa>` check it.
* Python is used only as thin glue (text generation and a text check, under a minute, small memory).
